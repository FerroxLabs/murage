# Windows backup transport source packet

This adapter is **not wired into Windows platform admission or packaging**. No native Windows compile/runtime proof is recorded. The controlling record is `.planning/post-0152-review/B20-WINDOWS-TRANSPORT-CONTRACT.md`.

`protocol.mjs` encodes the trusted caller request and validates helper control state. `transport.cpp` is the unelevated adapter. It accepts only `--parent <actual PID>`; all request values travel over private inherited stdin. The helper never accepts an executable argument. Its fixed sibling `age.exe` must match the recorded upstream SHA256. Signing/attestation policy and trusted installed-helper resolution remain a separate integration gate; this source does not enable an unsigned-release exception.

The request is decimal metadata byte length plus LF, exact UTF-8 metadata, then exact normalized key bytes. Metadata has ten LF-separated fields: version `1`, nonce, `private-stage|decrypt`, parent PID, approved parent directory, ciphertext path (empty for private-stage), key byte length, maximum bytes, operation milliseconds, close milliseconds. Neither metadata nor control includes the identity. The helper reads the exact key length into a separate zeroed-on-exit array. The caller writes START only after PREPARED. For decrypt, await CHILD_CLOSED before inspecting the authenticated plaintext. The caller retains the process and guards through its final source hash/inspection, sends RELEASE **and ends its stdin writer**, validates RELEASED and waits for actual zero helper close before cleanup/publication. Native processing requires actual EOF after RELEASE; any trailing byte fails closed. Missing receipt or unconfirmed close requires retention. The helper never recursively removes scratch.

Control frames on helper stderr are tab-separated ASCII: version, nonce, event, fields, LF. PREPARED fields are ciphertext volume serial/file ID/size and private-stage volume serial/file ID (ciphertext zeros for private-stage). CHILD_CLOSED carries `0` and the exact total plaintext byte count; any other child result fails with helper exit72. The caller feeds every stdout chunk length to `protocol.plaintext()` and waits for `plaintextComplete` before flushing/validating: stderr delivery may precede earlier stdout bytes, and helper stdout remains open until release. RELEASED carries the final held-ciphertext SHA256, or `-` for private-stage. Commands are START, RELEASE and terminal CANCEL without extra fields. Unexpected/duplicate input fails closed. Stdout carries plaintext only; age stderr is separately drained and zeroed, never forwarded. The private stage leaf is `.murage-backup-<nonce>` under the supplied pinned parent. A retained stage is therefore deterministically discoverable by the trusted caller even if preparation fails before PREPARED.

Parent authentication checks actual direct process PID, same user SID and unelevated token. It deliberately does not invent a desktop executable chain for a utility or headless process. The eventual trusted caller must independently admit its installed adapter resource and operation policy. No renderer-supplied path/executable API is included here.

The watchdog enforces handshake/operation deadlines and parent loss, including blocked stdio. It exits without a release receipt on failure; kernel closure kills the job. Only observed successful child exit, drained streams and explicit guard closure can lead to RELEASED. A timeout/cancellation is never represented as confirmed cleanup. Whether actual pinned age retains the extra inherited guard handles remains a mandatory Windows fixture gate.

Source/fake check: `node --test native/backup-age/protocol.node-test.mjs`. Tests cover the actual codec/state machine and explicitly labelled source invariants. They do not prove Windows API behavior. The manual build entry is `node scripts/build-backup-helper.mjs`, requiring existing Windows x64 MSVC/SDK; it uses C++20, `_WIN32_WINNT=0x0602`, and `Advapi32.lib`/`Bcrypt.lib`. Its injected command tests pass, but no compiler or native binary has been run. Output is `dist-native/backup-tools/win32-x64/murage-backup-age.exe`; packaging, signing and platform admission remain separate.
