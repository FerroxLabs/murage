# Flux single-key backend package

Outcome: one authoritative Flux credential across chat, search, images and transcription, with explicit selection for differing existing keys. Scope: pure credential resolution/consolidation policy and focused regression tests; root owns persistence, HTTP/Electron seams, active-work fencing and assignment migration. Other providers and owner credentials are excluded. Never read owner data or call providers.

Acceptance: equal credentials can converge without losing identity; differing credentials refuse implicit selection; revisions fence stale choices; disabled credentials never become implicitly active; unrelated provider records survive. Existing IDs needing migration are returned explicitly so the caller can fence active work and remap assignments before persistence. Read-only resolution performs no migration.

Checks: Node pure-policy tests and existing affected Flux resolver Vitest tests, using fake strings only. Maximum two verification rounds, two corrections per issue. Stop after accepted helper tests and concrete root seam instructions, or report the unmet requirement. Integration/runtime/UI checks remain root-owned.
