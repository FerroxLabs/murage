# Memory V2 migration kill suite

## Purpose

Prove that an interruption at each migration write or fence preserves the owner's forgotten data boundaries and that recovery reaches the same durable result as an uninterrupted migration. Give the builder and reviewers one inventory that fails when a write, fence, or privacy check is missing.

## User promises

- An interrupted upgrade keeps forgets effective for recall, a running turn's release, and notebook re-import. Forgotten words are absent from all four stores once their respective removal work has completed.
- A standing revoke keeps its exact holds until the applicable walk is proven. Restart replays unfinished work and preserves readable control records, unaffected imports, ready views and live session proof.
- Upgrade, backup, restore and older-build open preserve the v13 file contract. A completed migration converges without reintroducing an idle loop or making the owner's turn wait on a local memory budget.

**Owners.** I owns the runner, M5, the kill matrix and compat. W owns open/commit/wakes and the jobs trigger. C owns the actual revoke walker, P4/P5, V1 and V5. A owns the applier, M3/M4 and recall term storage. H owns the M6 collector and its proof state. F owns retained release and its memo/input proof. G and the FORGET-ATOMIC lane own notebook import and forget respectively. The helper index owner (MEMW) owns postings and scrub. E owns capture and checkpoint debt; the consolidation owner owns family membership. The selfheal-1021 owner owns M7. J owns the reusable gate rig and P-suite contract. MAIN owns selection of the combined product pins and older-build CI provisioning.

### How to read the tables

Paths are under `server/memory/` unless a path starts with `server/`. A source cell ending in a statement's execution line may refer to SQL prepared earlier in the same function. Every executable row runs the entire judge below at the observed cut. The invariant column names the extra outcome the site specifically distinguishes. Each mutant is identified by its row ID and described in the last column. For shared statements, the instrumented stack and branch/target key supply the row ID.

- **T** means before the outer commit or after the indicated statement while the outer transaction is still open. Death leaves the prior committed snapshot and prior cursor. On rerun, the selected work has to occur once with its cursor. Inject both before and after the statement.
- **A** means an autocommit statement. Cut immediately before and after it. After the cut, only the prefix of individually committed writes survives. At a trigger body inside that statement use T semantics for the statement, even without an explicit BEGIN.
- **C** means a witnessed outer commit. Cut immediately after successful COMMIT and before publication of the wake or other process state. The batch and its progress survive. Resume in a fresh process and handle. Killing before COMMIT and rolling back have their own row IDs.
- **F** means a fence, guard or process-only step. The file reflects its last witnessed commit. State the guard's observed inputs/outcome and recover with a fresh handle. For repeated SQL, force the first and last relevant invocation and a seeded interior invocation when the batch has one.
- A mutation about a committed postcondition at a T cut must be exposed by the selected case's replay and final comparison, or by deliberately admitting an early commit at that site and reading its forbidden prefix. Reaching a SQL line alone is never a mutation receipt.

### Generator and crash protocol

1. **Plan.** Use existing instrumented connections and the booted memory gate server/helper harness. Keep one reviewed data record per ID (the tables above are the initial inventory), with owner, source fingerprint, entry point, fixture variant, cut side, required trace effect and expected assertion/mutant. The separate reachability/SQL extraction runs in CI against the same pinned tree and emits the expected keys. Exact sets must match, including explicit reasoned dispositions for out-of-scope writers, unreachable guarded branches such as current R-stub-off, and negative branch obligations such as no new fold during M2. Abort on a duplicate ID, unbound site, unknown reached SQL, empty plan, skipped/todo test, unbuilt contract dependency or missing row. Source fingerprints resolve source lines on each build. A line number change alone does not change the row ID.
2. **Enumerate.** Generate concrete `it.each` cases from the reviewed inventory and each row's before/after/fault and fixture cases. Each executable row receives at least one forced scenario. The 50 named seeds perturb fixture/slice/restart order with a deterministic allocation that covers all forced cases and a 50-seed random boundary walk. Keep a fixed 50-seed floor across the aggregated suite. Each shard receives a fixed partition of the same plan. Every required `(seed/fixture, site, side, judge, production entry)` receipt is keyed and checked exactly once for the forced plan. Extra random walk hits are keyed separately. Keep a finite scenario per SQL operation, then use shard parallelism or reuse immutable starting backups to control cost. A missing row, an unreachable cut, callbacks that silently skip work, a killed control, and an unjudged reached site each fail in CI independently.
3. **Arm.** Seed through real APIs where owner/regression behavior depends on them. Use SQL only for historical fixtures and exact state observations. The parent arms a single source/SQL/branch occurrence in the real child. Observe at `BEGIN`, before/after the actual `.run/.exec/.get/.all`, trigger statement, callback or file write, and before/after the outer transaction result. For a nested statement with no JS interpose, use the test instrumentation of that real trigger definition to emit a synchronous tap at its statement ordinal within the same transaction. Preserve production SQL, trigger ordering and branch choices in that instrumented case. Check W-COMPAT with untouched schema and repeat the enclosing commit kill on the untouched trigger. No test tap performs a business write or counts merely entering a wrapper as work. All setup, including held target/control wire release before Forget, precedes mutation/fault activation.
4. **Interrupt.** On matching trace, the child signals before returning to the production path and parks. Terminate the exact spawned child PID with no disposal callback. For ROLLBACK and statement-abort variants force a real checked SQLite error at the scheduled position, trace the actual rollback, then park and kill. Separately inject a caught M6 marker statement abort and assert the attempted write plus absent marker before fresh recovery. A commit case requires a successful outer COMMIT or a successful durable autocommit statement on the traced handle (txn identity and changed rows). A stalled probe, SAVEPOINT RELEASE, failed commit or a cache reset on the same handle counts for zero commit cases.
5. **Observe.** Await the child's exit. Open a distinct reader connection to the private profile and establish the recovered SQLite snapshot before scheduling any new migration writes. Preserve the live WAL and helper artifacts for that snapshot. A new worker starts via actual listen/open. At M6 assert fresh collector identity and exercise check, cite and message work independently. For P2, exercise a surviving real observer holding a turn bound to its own connection on the private same file. Build that held turn *before* the forget and hold it at the actual fake-engine boundary. Only the child runs scheduled migration work until the fault, and the surviving observer releases through production on the recovered committed prefix. Keep this observer connection distinct from the dead writer and track its handle/generation. An execution that kills the owning server has no surviving in-memory turn. In that variant also prove the real process exit emitted no unauthorized bytes and production resume/rebuild at startup cannot reuse the revoked durable receipt. Take independent reproductions of the same cut for destructive P checks, so P3/V1/V5 samples or P2 refusal writes cannot affect the canonical migration trace. Check the exact trace key and every named completed judge key before continuing.
6. **Resume.** With the observer probes out of the writer schedule, start a fresh worker from the recovered file and run the same remaining stimuli through real wakes/checks. Preserve C's actual subscriber and runner, A's routed applier, and H's upkeep/lap under deterministic scheduling, and preserve the intended waiter/live interleavings. No drain helper ahead of a cut, preinstalled completion marker, imposed done state or fake elapsed-backoff result. The harness may gate clocks and I/O at the boundary, never supply the runner's answer. For retained checks, allow fixture clocks/grants sufficient for the case. A cap refusal cannot pass under MAIN ruling 2186.
7. **Reconcile.** SITES.md and CHECKLIST.md list operation line, real entry line, fixture, trigger, expected assertion line, tag for targeted mutant and observed receipt path. Independently assert exact equality of expected and observed key sets, then assert per-key behavioral outcomes. Negative inventory mutations delete one case (also delete any associated local list), suppress a tap, drop one judge or signal the wrong transaction. Each must fail the specific completeness check. Mark skipped, unimplemented and newly discovered candidates as failures with their semantic key.

## GAP-CHECK

### Fixed

- Failure path. An owner has a forgotten record in both a live recall view and a rolled checkpoint while migration stops. The earlier record-only predicate could miss postings and member text. Each store now has a positive presence check, its own durable obligation and its own mutant.
- Failure path. If the C writer dies after a frontier/hold write or H after just one dependent deletion, the old harness already drained or had already completed the lap. Cut at those SQL writes and at proven commits, then reopen with new C/H process state.
- Safety/data. A held turn has a valid frame or lookup receipt before Forget and attempts a release after a kill. The real wire validation must prevent the old bytes from leaving. A separate surviving observer handles a real retained request and a fresh owning process handles resume.
- Purpose gap. Without a ready watermark the full-day run can finish with a million-row journal. R-bounded creates the ready reader, proves actual view effects and asserts the bound with a build pin, plus a separate no-build cell.
- Purpose gap. If control turns on only the killed path write journal entries, exact recovery cannot be compared. The canonical reference and faulted writer get the same input log and probe writes remain on independent cut replays. The oracle then catches identity substitution and empty journals.
- Rule conflict. The enabled fold callback can try to enroll a new cohort while the M2 contract says no fold. C-fold-entry/new distinguish existing durable fold continuations from new enrollment. A newly enrolled cohort on the migration path fails the contract, with C owning the runner behavior and I owning this gate.
- Rule conflict. A resident older build may reopen a file with queued legacy keys, and an artificial current-version validator can mask a lost tombstone. Use the true old executable/module tree and actual v13 file plus real restore/downgrade output.

### Parked

- None. The Cloud reset/undo contract remains owned outside desktop migration under section 8 CL-1 and adds no new behavior to this note.
