## What dev/1022 changed under the design
- **A1 Stop confirmation moved earlier** (dev/1022 f6e18476c9). `confirmedStopGenerations.add(stoppedGeneration)` now runs at index.ts:5134-5137, right after a confirmed close and before the ownership check and the non-dispatching guard (:5146). Rev 4's premise that a dispatching Stop never reaches the add is gone. The rule stands: `ownerStopReceipts` is still recorded right after the interrupt resolves (it also carries "unconfirmed" from the throw path :5125-5132, and initialises a later O). The builder may now write "confirmed" next to :5136. That is also where W9 mutant (e) must be placed.
- **A2 Rebuild owner Stop branch (new in dev/1022, 41b4fb6bdc).** `interruptDirectThread` no longer releases a rebuilding run (:5094 returns). The release moved to `cancelDirectTurnDispatch(botId, threadId, note, ownerStop)` (:5347-5380). When the generation is already refused it returns null (:5351). Otherwise it owes an owner Stop row (`oweOwnerStop`) and confirms the generation (:5363-5373). Five callers pass ownerStop=true: interruptDirectThread itself (:5084), the conversation Stop (:14704), the routine Cancel (:22824), POST /api/local-computer/interrupt (:36666, route :36624) and /api/bots/:id/interrupt (:38006, route :37923). The O guard belongs inside cancelDirectTurnDispatch so that all five are covered by one site. W9 already drives the conversation Stop and the Cancel. W9 gains driver variant (vii): the same D3 fixture is stopped through each of the two /interrupt routes, with the same expected outcome as (iv) (exactly one refusal row, run CANCELLED, 0 rings). SITES.md lists all five callers. For a routine D3 turn this would contradict W9 (iv) ("nothing to close" -> exactly 1 refusal row). So when an O is registered for the generation, this branch must not confirm, owe a Stop row or set "confirmed" on O. O then freezes at release with ownerStop unset. Ordinary conversations keep the dev/1022 branch byte for byte. The live builder already does this (feat/1022-O36 index.ts:5494, `!refusalObligations.has(run.generation)`; Fable and Opus "FIX OK" on cdcb9ecb16, n4:4590/4592). Rev 5 writes it into the design so W9 (iv) has a stated rule.
- **A3 Done-notification gate** (:14022). dev/1022 adds `&& !commandRefusal` (:13782: command_needs_session / resume_model_changed). A routine turn that ends on a command refusal no longer sends the "done" frame from this site. That was already right for O36, whose outcome ring comes from the outcome commit (onRunCompleted/onRunFailed with `routine-run:<runId>`), never from this frame. Witness obligation (no new row): W12 (ring fence) and the design-wide "one end per run" ring identity still counts frames from all sources, so a command-refused routine run must still ring once through onRunFailed.
- **A4 Release sites.** 5010 is gone (A2). 5279 is now the rebuild branch at :5375. Rev 4 left out the rejection token release (`directRuns.release(token)`, base :4723, now :4808), which is now listed. R5 lives inside `DirectThreadRuns.release`, so every site is covered either way. The list is the SITES.md seed (P1).
- **A5 Electron receipts.** attention-main/router gained lines above the cited blocks. The cited connector-reconnect durable receipt path (attention-main.mjs:339-352) and `known()` (attention-router.mjs:367-378) are textually unchanged.
- No seat-wait code changed (`git diff` of index.ts has no seatWait/seatGranted line). The flaky W6 retry stage on feat/1022-O36 (Astra/Fable/Opus H on cdcb9ecb16, routines-restart-boundary-api.test.ts:773) is therefore not a dev/1022 seat-wait change. It remains the builder's open High.
