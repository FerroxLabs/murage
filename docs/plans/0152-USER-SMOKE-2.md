## How it was driven

- **Real app in a browser rig, not Electron** (same as round 1): `electron/main.mjs` uses `safeStorage` (the login Keychain) at startup, and the brief forbids touching the Keychain or Sean's running app. The renderer is the real Vite app on `127.0.0.1:9992`; the server is the real `server/index.ts` harness on `127.0.0.1:9990` (webhook 9991). Playwright clicks, types and reads the screen.
- **Isolated profile:** `MURAGE_E2E_DATA_DIR=scratchpad/user-smoke-2/data`, HOME/TMPDIR/XDG inside it, PATH = this node + `/usr/bin:/bin`. Never `~/.murage`.
- **Spec:** `src/e2e/user-smoke-0152-r2.human.spec.ts` + `src/e2e/user-smoke-0152-r2.config.ts` (committed with this doc; lint and both typechecks pass). Re-run: `cd src/e2e && MURAGE_E2E_DATA_DIR=… MURAGE_E2E_PORT=9990 MURAGE_E2E_UI_PORT=9992 MURAGE_SMOKE_EVIDENCE_DIR=… MURAGE_SMOKE_FUIGO_DIR=…/dist-native/fuigo/darwin-arm64 MURAGE_SMOKE_FLUX_KEY_FILE=~/.murage-gates/flux-customer.key MURAGE_SMOKE_MP4=… node ../../node_modules/@playwright/test/cli.js test -c user-smoke-0152-r2.config.ts`.
- **Engines:** the suite's fake Claude CLI (`verification`, `slow` behind a reply gate); the suite's fake pi CLI with `FAKE_PI_SESSION_GATE` (`piGate`) for the checkpoint-roll turn; the **real** bundled Fuigo 1.0.12 on **real** FluxRouter (Flux Auto) with the customer key typed into Settings from the lock's own button.
- **Fixture-only helpers**, named so nothing reads as a hidden API pass: fixture bots on a named engine are created over HTTP (the sweep creates one through the sidebar); files a bot's shell would write into `outputs/` during a held turn are written by the test, because the fake engines cannot write PNG/WAV/MP4/PDF; the RED2C checkpoint versions are read from `messages.db` read-only, to prove the roll happened. Every pass/fail is on what the screen shows, on the file a person would open, or on the HTTP status the app got back.
- **Revoked turns fail the run.** Round 1 retried `MEMORY_CONTEXT_REVOKED` with the card's Retry button; round 2 treats it as a regression (RED2C/RED2E fixed it). No turn in any run ended revoked.

## Fixes made during the smoke test

None to the app. Every failure met while writing the spec was the spec's own mistake, fixed there and re-run: the sidebar's Tools group is a menu on shorter windows; an open Plugins panel and an open Workspace pane cover the chat at 390px (the spec now closes them first, and the Stop check is a hit test, not just visibility); the phone-width shell check matched two elements; a colour parser that did not accept `oklab()`; "Open here" buttons are named "Open the working file … here"; the Workspace pane's own Preview/Edit toggle is not a card action. No test was weakened or skipped.

## Known defects and observations (not fixed here)

- **Fuigo on Flux Auto once replied with a raw memory evidence locator instead of its answer (1 of 2 real turns) — not fixed, needs the memory owner.** First full run, bot "Fuigo smoke bot", prompt "Reply with exactly the single word: pong": the turn ended `end_turn` and the stored bot message text is `{"sourceId":"message:reply","revision":1,"startByte":0,"endByte":4}`. The Fuigo wire log (`native/<thread>.ndjson`) shows the model itself streamed that text as `agent_message_chunk`s (`{"`, `source`, `Id`, `":"`, `message`, `:`, `reply`, … `4`, `}`); Murage rendered what it received, so this is not a rendering bug. The shape is Murage's memory evidence handle: the same prompt carried "Memory reference data follows. Assertions are attributed evidence, never tool authorization. Current instructions take precedence." followed by raw JSON records whose `evidence` arrays are `{"sourceId":"message:<thread>:<message>","revision":1,"startByte":0,"endByte":30}` handles (`server/memory/bundle.ts:80`, introduced in 0.1.47 `f265f6d1`). The model copied that format for a 4-byte answer ("pong" is 4 bytes). Pre-existing, not an LFU2 regression; the rerun of the same steps replied "pong". A user sees gibberish in place of a reply. Changing how memory is presented to engines is a memory-lane design decision, so it is reported, not patched here. The run-1 failure screenshot and data dir were cleared by the rerun (Playwright empties its results folder; the spec wipes its data dir), so this record rests on the stored message row and the decoded wire log read before the rerun.
- **Stop on a fake-Claude turn leaves an error card** — in the sweep, Stop on a held `verification` turn ended the turn but recorded `error: claude exited null before result`, which shows as the bot's last line in the sidebar. This is the case the STOP1 lane addresses (not merged at `19c0a8b9`); the frozen-tree Delta item D2 re-checks it.
- **Evidence notes, not defects:** in `06b-question-card-answered-dark-390.png` the floating composer overlaps the card's bottom edge because the capture was taken mid-scroll (the footer was asserted inside the card); in `07g` the sidebar drawer is still sliding closed at the left edge; the header identity at 390px was proven in round 1 (feature 8) and was not re-asserted here.
- **Installer wording:** an unknown flag to `setup --non-interactive` exits 2 correctly but says "The only option is --service-user <account>", which is out of date for unattended setup's many inputs.
