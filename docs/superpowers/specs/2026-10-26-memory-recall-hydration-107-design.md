# Memory recall returns nothing on Sean's data (1.0.7, fix/107-memory-recall-hydration) - design r2 (r1 + Fable AGREE-WITH-CHANGES and Grok APPROVE folded in)

## What was measured (copy of rh3-data/pristine, int/107 893e0768f, bench server/memory/recall-realdata-bench.test.ts)
- Shape: 93,648 active records, 463k evidence rows, 95k sources, 6.7M deny_memory rows. 7 bots, 61 real-shaped queries (the owner's own recent words per bot thread; never printed).
- Hydration cost is NOT the problem. Per word-index candidate, a full `readableMemoryRecord` is p50 1.5 ms, p95 3.6 ms (n=1,219); every step under 0.5 ms p95 (record row, derivation walk, human check, evidence page, write-time lookup, withheld-message walk). `plausiblyReadable` per batch p50 7 ms.
- With an UNLIMITED lineage allowance, 1,216 of 1,219 plausible candidates throw `MEMORY_REPLAY_LIMIT` and 3 are refused: recall is empty whatever the budget. Search turns that throw into `partial`, which is the `cause=MEMORY_RECALL_HYDRATION_LIMIT outcome=empty ms=264..1168` line in Sean's log (well under the 1,000 ms limit: no time limit was reached).
- The throw is `writetimeRecordRefusal` (readable.ts:178): `memoryLookup` reads `checking("pending")` for the record or its evidence sources. 10 non-audience `*` pending windows (kind `line`, phase `flow`, since lsn 215..419, next lsn 437) cover every scope.

## Root cause (deny-read.ts memoryScopeVerdict / batchRecords / memoryVerdict)
DESIGN-WRITETIME 1 says an object is held "checking" only when `since <= created lsn`. The reader takes `created` from a `created_lsn` COLUMN of memory_records / memory_sources (`hasCreatedLsn`). No shipped schema has that column: the S3 trigger stamps the separate table `memory_record_lsn`, and sources have no stamp at all. So `created` is always null, and null means "checking" under ANY pending window of the scope or `*`. Every non-audience revoke (Sean's log: branch-change, identity-write-pip, line forgets, many a day) therefore blanks all of memory until its flow phase ends; under his io budget that is most of the time. Since 1.0.2 S4 (b644c4e48).

## Design
1. Records: `created` = `memory_record_lsn.created_lsn` for that version (one PK seek, batched in batchRecords). A version with no row was made before v10: its created lsn is below `lineage_upgrade_lsn` (memory_lineage_lsn_meta), used as the bound. No meta key: null, "checking", as today.
2. Sources: new `memory_source_lsn(source_id, revision, created_lsn)` WITHOUT ROWID, stamped by an AFTER INSERT trigger on memory_source_versions (same shape as memory_record_lsn_insert, added to WRITETIME_TRIGGERS so the boot check covers it), plus meta key `source_lsn_upgrade_lsn` = memory_lsn.next at the migration. A source version with no row existed before that lsn and is bounded by it; no key: "checking". Windows opened before the migration keep covering old sources until their jobs finish (unchanged); every window opened after it covers only what was made after its since.
3. Recall time (only after 1 and 2 make candidates readable: ~120 candidates x 1.5 ms > the 100 ms TOOL_LINEAGE_MS that `readableMemoryRecord` charges for the WHOLE read): recall's search allowance gets the search's own hydration limit as its time budget (turn 1,000 ms, tool 3,500 ms), so the search ends on its own limit, partial with what it proved, never on a stricter hidden one. The bundle re-proves the selected hits on a fresh allowance of its own (recallProofBudget, 100 ms, as today), so a search that spent its allowance no longer makes the bundle drop every proven hit (bundle.ts:513 shares `recall` today).
4. Unchanged: every candidate on every path still goes through readableMemoryRecord; withheld stays withheld; "checking" still refuses (limit error, never persisted); a time cut returns what was proven, flagged partial. Per-turn cost stays bounded by fixed constants, never by history.

## Failure list (each gets a test)
F1 a record made after a pending window's since stays "checking" until marked. F2 a pre-v10 record under a window whose since <= lineage_upgrade_lsn stays "checking". F3 a source revision made after since stays "checking"; one without a row under a pre-migration window stays "checking". F4 no meta key: today's behavior exactly. F5 an audience reader keeps every audience-only mark (no change to NOT_AUDIENCE_ONLY). F6 the trigger missing at boot fails the WRITETIME_TRIGGERS check as the others do. F7 the bundle never shows a hit its own re-proof refused.

## r2 changes (Fable AGREE-WITH-CHANGES, Grok APPROVE on r1; these override r1 where they differ)
- D1 records: `created` = the stamp of THE VERSION READ. A versioned ref uses (id, version); an unversioned ref (deny-read.ts memoryVerdict, record branch, latest version) uses the stamp of that latest version, never the earliest. No stamp row: bound = `lineage_upgrade_lsn` (memoised per lookup); no meta key: null = "checking" (today). D1 is sound only together with D2 (evidence added after a record's creation, authority.ts:150, is caught by the source check in readableMemoryRecord).
- D2 sources is schema v13 WITHOUT a meta key (memory_lineage_lsn_meta's CHECK(key IN ...) and the validator's exact key set stay as v12): new `memory_source_lsn(source_id TEXT NOT NULL, revision INTEGER NOT NULL, created_lsn INTEGER NOT NULL, PRIMARY KEY(source_id,revision)) WITHOUT ROWID` + `memory_source_lsn_insert` AFTER INSERT ON memory_source_versions (same shape as memory_record_lsn_insert). An unstamped source version is bounded by `coalesce((SELECT min(created_lsn) FROM memory_source_lsn), memory_lsn.next)`: every version inserted after the migration is stamped, so every unstamped one predates the first stamp (or, with no stamp yet, now). The first non-null min is memoised per db handle (it can only stay or rise; either stays a valid bound); with no stamp yet it is read per lookup. Unversioned source ref: the stamp of its latest revision. The new table and trigger are NOT added to WRITETIME_TABLES / WRITETIME_TRIGGERS (those are the v10 set the v10->v9 step drops); they are their own v13 objects.
- v13 migration: MEMORY_SCHEMA_VERSION 13, schema text = v12 text + the two objects, accepted-schema fixtures for v13 (exact sqlite_schema), upgrade v12 -> v13 creates them empty (constant time, no backfill), and a v13 downgrade branch like the v12 one (schema.ts downgradeMemorySchema): `version === 13` drops the trigger then the table; MemoryDowngradeTarget and the recovery CLI accept 12. v13 -> v12 -> v13 starts the table empty again, so every source version made before the re-upgrade is unstamped and bounded by the first new stamp: windows opened before the re-upgrade keep holding.
- D3 unchanged, plus: `recall.hit` (bundle.ts:582) uses the proof allowance, not the search one. The node cap (3,000) still binds; the bench reports time cuts and node cuts separately.
- Bench (Grok Lows): refuse any data dir not under an explicit scratch root (RECALL_SCRATCH_ROOT); log only fixed codes, never error.message or st.error.
