# U1-G3 A2 Basic and feedback evidence

The dependency-free matcher discovers original UTF-16 Basic spans with cached gap/successor/value endpoints. Tracked edits preserve original payload counts, widen intersecting replacements, retain deletion events and respect insertion endpoints. The feedback scrubber uses the same matcher around its original relative chain; its JWT rule has the specified linear start constraint and preserves the leading capture.

RED: `evidence-a2-red.log` records nine failed assertions and seven preservation passes. The feedback case observes the existing scrubber returning the Basic credential; matcher/forwarding cases use the explicit no-protection interface stub.

GREEN: `evidence-a2-final-green.log` records 119 passing assertions across the Basic suite, existing screen-envelope suite and release-workflows. This includes 20,000 multi-rule forwarding cases against an independent reverse-edit interpreter, 30,000 feedback JWT comparisons plus the five named edge cases, grammar/EMPTY/encoded-gap examples, malformed escapes, thrown-rule retry/interleaving/idempotence and truncated-error coverage.

The matcher and complete feedback caller pass CPU best-of-three limits of 40 ms at 64 KiB, 60 ms at 128 KiB and 500 ms at 1 MiB for the required adversarial shapes. The 8/16/32 MiB short-header test bounds visit/allocation counts, their doubling ratios and output size. The counted work is algorithmic work, not a claim about peak process RSS or wall-clock latency.

`a2-final-types-run.log`: app, server and conformance-tools typechecks all exit zero. All execution used the required container wrapper. Every committed new test is registered in ci/gate-tests.txt.
