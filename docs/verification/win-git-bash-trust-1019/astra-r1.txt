DISAGREE

The design has sound security goals and mostly accurate source citations, but it is not yet decision-complete or buildable. Its required artifact references, Fuigo execution contract, and concrete native protection mechanism remain unspecified. Defaulting every case to untrusted is safe, but does not deliver the fixed scope.

Open-question answers, corresponding to every row in §6:

- **Q1 — Artifact provenance:** Support release-qualified, engine-selected installed Git, including per-user installations. Require authenticated reference bytes and a complete launch/runtime inventory before approval. Discovery alone cannot establish authenticity; current packaging does not establish bundled Git Bash.
- **Q2 — Fuigo binding:** Use an enforced, versioned launch contract acknowledged by the actual Fuigo process before execution. Define its fields, capability negotiation, lifecycle and engine-side implementation. Neither a model-supplied pathname nor a post-execution observation suffices. Missing capability means no exception, but Fuigo support remains required for completion.
- **Q3 — Same-turn integration:** Target the current reader and identify the exact NL-SAMETURN integration revision. Preserve plain/cd, Bash/sh and LF/CRLF acceptance cases. Do not recreate `shellBody` or assume a currently absent rejection.
- **Q4 — Replacement/runtime attacks:** Retain handle protection and authenticated runtime verification. Specify how actual image selection is constrained; hashing a declared dependency list does not itself establish that those are the images execution loads.
- **Q5 — Updates:** Revoke new admissions on Stop or environment change, drain protected children, then release handles. Restart and reverify after an update. A UI Stop event alone must not release protection while a child remains alive.
- **Q6 — Conservative ACLs:** Keep unknown cases untrusted. Define applicable replacement rights precisely and qualify ordinary standard-user installations. Permission to create an unrelated sibling must not automatically be described as permission to replace the protected child.
- **Q7 — Budgets:** Retain the proposed bounds pending measurement. Count pending, canceled-but-running and draining verification work against capacity; timeout must never create reusable trust or unlimited outstanding workers.
- **Q8 — Bare Bash tightening:** Accept Windows-specific tightening, but define it for all missing-state branches, not merely commands “offered” for the exception. Keep unrelated interpreters and POSIX behavior unchanged.
- **Q9 — Negative controls under No limits:** Assert absence of trust and preservation of findings separately from final approval. An eligible No limits command can correctly run despite failed Bash verification.
- **Q10 — Kept-set conflict:** Preserve explicit owner denies and wipes as required by this brief, plus the already ratified `murage-engine-hooks` rule. Adopt those expectations in the combined-lane tests; Git trust must introduce no policy exception.
- **Q11 — Settings/UX:** Add no preference, enrollment question or repair card. Preserve Advanced controls and their stored values. Automatic qualification is consistent with G9; packaged proof must show unsupported-shell selection and Stop/restart remain understandable and usable.
