### Source findings that stop resolver integration

The supplied source is `_opencode-1.19.5`. These are source
findings, not real-binary reproduction results. No provider or network call
was made. The builder has not expanded the agreed candidate/no-cache rules.

1. `packages/opencode/src/config/config.ts:276–289` loads a global,
   extensionless `config` as TOML, after the three JSON global candidates.
   `provider` and `model` can change `result.model`; it then writes
   `config.json` and removes the legacy file. The design's exhaustive
   candidate list does not contain this extensionless path. Adding it before
   a turn leaves all listed candidate tuples unchanged (ordinary directory
   timestamps are deliberately excluded). A cache hit thus retains the old
   default model and cannot see the migration's JSON write until the engine
   starts. Pinning the cached model avoids claiming an alias bypass from this
   example, but does not fulfill the promise that a persistent config change
   moves the key on the next turn. This is not an edit between check and spawn.
2. `packages/opencode/src/auth/index.ts:59–61` returns parsed
   `OPENCODE_AUTH_CONTENT` instead of reading `auth.json` when supplied.
   `config/config.ts:331,370–405` takes `authSvc.all()` and loads remote config
   for every `wellknown` entry. Murage's local `childEnv` keeps this variable:
   it is absent from both `PROVIDER_CREDENTIAL_ENV` and `ROUTING_ENV`, and
   OpenCode's transform does not remove it. The design specifies bypassing
   cache for wellknown entries in `auth.json`, but not this alternative auth
   source. A fixed inline wellknown entry can load different remote provider
   URLs on successive starts while all listed local key inputs stay fixed.
   Merely hashing the inline value would not solve that case; the no-cache
   condition would need to cover it too. This is a config-service remote
   layer, not a plugin or proxy rewriting URLs under the stated Limits.

## Realpath cache (7 Nov 00:12Z ruling)

`OpenCodeDestinationKey` now bounds its instance realpath cache to 64 paths.
Each path entry validates device/inode and the complete file stat signature;
the hashed tuple remains exactly dev, ino, size, mtimeMs, ctimeMs, realpath.
Missing or unreadable paths evict their entries. Tracking errors fall back to
native realpath resolution without saving an entry.

Parents are checked with lstat, including the file symlink, every traversed
ancestor and every component reached through symlink expansion. Relative link
paths process `..` after expanding intervening links. Shared components are
checked once per read. For a stable working set fitting the cache, syscall
calls are N statSync + C lstatSync + the existing account check (one statSync
when its DB is absent), zero realpathSync/readlinkSync/readFileSync. N is the
existing file() stat count (CLI, candidates and file tokens); C is the number
of distinct traversed components of existing paths, including roots/leaves.
A changed directory tuple conservatively re-resolves without hashing directory
timestamps. No target Mac latency result is claimed; the real test's two
median assertions remain unchanged.
