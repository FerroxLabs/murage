# A1 — retained lineage and bounded validation

This is an intermediate foundation slice. A2 supplies dispatcher/final writer integration; A3–A6 close the remaining sinks. It is not independently shippable.

## Changes

Concrete open-turn identities own a frozen reader, normalized retained refs and a nonrenewable release budget. A private WeakMap binds each generation to the exact SQLite connection that opened it; preparation and release reject an alternate connection even to the same file. References retain the strictest judge, copy origins, shown prefix lines and receipt scope obligations. Limits are 4,096 retained lines, 512 objects, 4,096 emitted attempts, 64 MiB, 16,777,216 work units and 65,536 statements. Validation charges work only; actual emission accounting belongs to the final writer under R1. Prepared pending-window optimization disables above 512 rows rather than granting access.

Receipt checks now include current record/source content state, source anchors and source edits for every reader, while preserving integrated owner/content versus audience distinctions. The dependency holder lives in a leaf module. Upstream parsing checks raw byte limits, preserves native errors and propagates release refusals; metered SQLite iterators close when a reservation fails.
