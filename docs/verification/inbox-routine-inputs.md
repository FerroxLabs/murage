# Incremental routine inbox inputs

`InboxRoutineLifecycle` owns the capped record projection, scheduled order, latest-start selection, current-routine link subscriptions and card suppression. The manager publishes run states, removals and whole-store replacements. Retirement uses a bounded successor lookup to refill a vacated capped slot. Replacement and rollback rebuild at the existing explicit owner/lifecycle boundary. Ready badge reads use the maintained aggregate. Inbox views materialize the maintained record projection; the legacy producer is confined to reconstruction before readiness.

Finite numeric run fact times contribute to the inbox. Missing, string, NaN and infinite fact times are omitted rather than encoded as timestamps. Scheduled ordering matches the scheduler's numeric coercion, NaN-at-oldest rule and signed infinity sentinels. This explicit malformed-data policy leaves the scheduler's retained records intact. Rebuild errors are reported, clear partial derived state and permit retry without escaping the deferred callback.

A card suppresses its record only while the card is in the 14-day window. Expiry activates the still-current record; a backwards clock adjustment restores card suppression. A badge access services at most 64 activation deltas. Larger jumps schedule the remaining fixed slices and return the existing preparing result until the aggregate is complete. This preserves the previous published phone badge during preparation. Current-routine message-link fanout also uses 64-entry slices. Inbox view anchors are queried live when materialized.

`routine-message-links.ts` maintains a storage-order radix tree in SQLite. Each prefix holds a maximum timestamp. A lookup reads at most 16 child ranges plus one member lookup, preserving timestamp ties and non-monotonic message times. Message insert, replacement, edit, delete and rollback update the index in the same SQL transaction through triggers. The once-only migration builds the tree before the database serves callers. Both loaded and unloaded Store paths use it; neither walks a loaded transcript to find a routine anchor. The tables and triggers are part of the shared message schema used by archive inspection and restore.

The fixtures in `inbox-routine-fixes.test.ts`, `inbox-routine-lifecycle.test.ts` and `routine-message-links.test.ts` cover malformed times, failure/retry, expiry, clock rollback, sliced batches, retirement/replacement, real producer selection, message-only link invalidation, stored-order mutation/rollback and the 100/2,000 size comparison. The shared control harness has no mapped inbox/link mutation command; these checks prove the manager/database contracts, while the fake chat workflow separately verifies fixture startup and conversation transport.
