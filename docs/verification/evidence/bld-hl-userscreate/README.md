# Private generated users.create

This redesign implements the binding MAIN rulings. The active acceptance matrix is `lanes/hl-userscreate/ACCEPTANCE.md`; the native rows in the earlier three lane reports are historical and superseded.

The review and tool arguments contain only identity and access values. Its request digest binds private generation policy version 1, including the recipient's final password setup in HighLevel. After lease acquisition, rate admission, final authority checks and durable dispatch/identity barriers, the dedicated transport creates 32 bytes with Node's OS-backed crypto randomInt. Each character selection and shuffle index uses rejection sampling. It validates the provider's four character classes before adding exactly one password field to the reviewed body.

One HTTPS POST goes to the pinned LeadConnector origin, with manual redirects and a maximum 30 second deadline that includes admission. No automatic write retries or secret retry state exist. The in-process template is one-use; durable company/email and approval records prevent replacements after restart. Read reconciliation remains available when the recipient creation flag is disabled. Owned password, serialized request, echo-check encoding and response byte buffers are cleared in finally; string references are released. This does not promise erasure of every V8 or TLS copy.

Provider policy was rechecked on 2026-11-11 against the [versioned Create User reference](https://marketplace.gohighlevel.com/docs/2021-07-28/ghl/users/create-user/) and [current reference](https://marketplace.gohighlevel.com/docs/ghl/users/create-user/). Both require at least 12 characters and all four classes. This check was documentation-only; no live provider request was made.

`HL_USERSCREATE_RECIPIENT_VERIFIED` defaults false and accepts only literal `true`. False gives “Add this user in HighLevel to finish setting up their access.” and an Open HighLevel link. True enables the full ordinary Add user review, including the recipient setup wording. MAIN may flip it only after Sean authorizes and completes a live recipient access check. This job did not perform that check and makes no email delivery claim. Existing production full-grant, verified-scope and owner provenance gates remain independent requirements; the fake fixture supplies them explicitly.

The retirement audit and independent Sol copy review are in this directory. Shared consumers were audited before deleting operation-specific native UI and submission infrastructure. Existing general clipboard, backup, capture, input, exclusion and process protection consumers remain.

All execution uses the requested it-remote wrapper, network none, fake provider only, one container at a time and a host-load wait above 60. The isolated control fixture uses launchVerificationServer and explicit-URL Doctor with temporary data/home. Its real fake-backed host approves an exact review, interrupts settlement after one complete create, then a fresh server process reconciles with one read and zero replacement creates. The generated provider request body is never written to evidence.

The injected synthetic-secret tests use HighLevelLeakGuardV2 for literal and encoded secret forms, binary SQLite/WAL, archives and declared public sinks. A real grep receives the synthetic needle on stdin and scans persisted tool results, review/approval records, transcripts and journals before close, after close and after restart. A positive control must be found, then removed; the actual scan must return no matches. Assertion failures report booleans, counts and sink names, never secret-bearing values.

Historical unsuccessful runs are retained externally under the job evidence directory. The initial full typecheck found three unused retirement declarations and was corrected. The second run passed full typecheck and the fake flow, but its live HTTP artifact scan saw an incomplete collection. Collection now retries the entire scan only when a concurrent filesystem change is proven, with the scanner's missing/unreadable evidence failures unchanged. Final results and mutation restoration hashes are recorded after execution.

No interactive packaged desktop, live recipient setup or universal crash-memory erasure is certified. The flag remains off by default. No Mac, real HighLevel call, user application data or billable service was touched.
