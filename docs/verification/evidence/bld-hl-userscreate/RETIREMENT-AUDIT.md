# Shared consumer audit before retirement

Repository-wide `rg` over code consumers found that the HighLevel password widget, persistent host, password generator in `src/lib`, password IPC, capture/input/clipboard coordinator, native session registry, nonce bank, submission parser and body reader served only users.create. Their production mounts, HTTP routes, preload API, channel classifications, types and operation-specific tests were retired together. The obsolete password mutant runner was replaced by the redesign's behavior mutants.

Shared `shared/highlevel-password.ts` remains: provider-body schemas and the private server generator consume its policy validator. Shared process-memory protection remains installed in main/server and retains its own tests. Native exclusion and password-native-addon code remain: exclusion adapters, platform qualification and process protection share them. The ordinary clipboard bridge, context menu, capture, input, screen-preview and backup credential infrastructure remain with their established trust boundaries; no password credential reaches them in this operation. Analytics privacy settings remain. The native Linux process qualifier remains independently useful and is not proof of total JavaScript erasure.

Old native submission URLs have no handler or route-policy entry. A request to either retired endpoint returns 404 before consuming a password body. Legacy password-bound pending journals do not match the new private policy and fail closed; they cannot acquire a new dispatch owner. They are not silently converted to a new create. Historical lane evidence remains historical, with the active acceptance matrix in `lanes/hl-userscreate/ACCEPTANCE.md`.
