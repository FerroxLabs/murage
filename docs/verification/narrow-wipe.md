# Narrow No limits wipe cards

Owner No limits checks recursive deletes, moves away and sync wipes of a whole
filesystem, drive, mount, home, homes parent, Murage data folder, project root
or top-level operating system folder. Disk erasure and repartitioning tools
also ask. The existing fork-bomb card remains under MAIN 23:15Z(c).

The action offers **Run** and **Don't**. For deletes and sync wipes the text is
“This would wipe {description}. Run it anyway?” For moves it is
“This would move {description} away. Run it anyway?” The descriptions are:

| Root | Description |
|---|---|
| Filesystem | the whole filesystem |
| Drive or mount | a whole drive |
| Home | your whole home folder |
| Homes parent | the home folders |
| Operating system folder | a whole operating system folder |
| Murage data | all Murage data |
| Project | your whole project folder |

Disk tools use “This would erase or repartition a disk. Run it anyway?”
The double-checker-fault text is “Murage couldn't finish checking this command
for a whole-drive wipe. Run it anyway?” The retained fork-bomb message is the
existing “This would start copies of itself until the computer stops responding.”
No v2 card wording is added.

Moving a file into a root, explicit nonrecursive native deletion, dry runs,
PowerShell WhatIf, literal wildcard filenames and removal of a final symlink
without following it run. A trailing slash or whole-folder glob follows the
link where that program does. Parser recovery preserves executable positions,
quotes, recursion and source/destination roles. Command size and nesting alone
do not create cards.

Verify only in an isolated fixture as described in [README](README.md). Keep
Doctor, the exact control commands, wait results, bounded messages and the
fixture log outside the repository. Use the launcher's fake engine; never
execute the destructive examples. The decision fixture separately tests
admission and release without executing an operation. Record both forms of
verification; a unit result alone does not establish a user workflow.

The root index is populated at boot and updated on committed root events.
The completion test counts task visits at 50 and 5,000 tasks, including the
store work. Its combined gate must pass after integrating the store owner.

The V3 pipeline resolves literal fields and shell state before classifying effects.
Nested shell argv, positional dispatch, find actions and xargs use the same
invocation reader. Literal interpreter calls are inspected without evaluating
code; computed joins, interpolation and scripts on disk remain opaque.
Uninvoked functions and blocks do not execute destructive effects.

Ordinary project `git clean` is exempt. Other users' home roots are protected.
Virtual mount types, including tmpfs, are excluded from the persistent mount
inventory. A new device boundary is confirmed by a bounded mount query; a
confirmation fault retains the boundary evidence. Path probes serialize by
filesystem key, quarantine timed-out keys, retain healthy workers and stop
allocating after sixteen quarantined workers. Registry build faults do not
retry on every query.

Each parser node carries a statement span. Recovery uses an independent,
iterative scanner, never the failing parser or walker. Readable harmless
checker faults run; a double scanner fault requires coarse wipe evidence.
Missing command text remains a distinct check-fault card. Context-reader faults
retain trusted request cwd and registered project context.

V3 proof sources are `server/wipe/corpus-v3.test.ts`,
`v3-regressions.test.ts`, `fault-v3.test.ts`, `perf-v3.test.ts`, and the mutation
witnesses. Keep the RED matrix, named mutant kills, private count-only replay,
comparison reports and disguised observations outside the repository. The V3
lane gates zero wipe-owned task visits and exact work equality at 50 and 5,000
tasks; the integrator owns the combined store-side P-7 gate. Native macOS mount
confirmation and Windows mountvol/subst checks require their platform runners.

MAIN WIPE-V3-PREMISE preserves unresolved whole option variables for rm and
Remove-Item: they may supply recursion, so a protected root operand still cards.
Recursive Remove-Item checks all positional, Path and LiteralPath operands.
Quoted wildcard filenames retain literal semantics. Interpreter stdin is source
only when no script file or module was selected; syntax-check modes stay ordinary.

The proof matrix records both W0 and W1, with already-green guards reported
honestly as PASS. Separate class witnesses cover Windows drive aliases, scanner
roles, virtual mounts, weak-state overflow and function-definition overflow.
