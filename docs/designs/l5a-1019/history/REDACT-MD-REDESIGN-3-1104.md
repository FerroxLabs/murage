## 1. Shared detector: findSecretLabels(line) -> [{sepEnd, wrapped}] (shared/md-secret-label.mjs, no imports, plus .d.mts)
1. Normalize a copy N with an index map back to the line. Delete `*`, backtick, `~`, `«`, `»`; delete `_` unless it sits between two `[A-Za-z0-9]` (`XAI_API_KEY`, `my_token` stay whole); delete a line-start run of `>`, `-`, `+` and blanks. Record D = original index of the FIRST deleted character on the line, or none. The line itself is never changed by this step.
2. Run `SECRET_LABEL = /(?:api[ _-]?key|apikey|secret|token|password|passwd|authorization|auth[ _-]?token|access[ _-]?key|private[ _-]?key)s?[ \t]*[=:]/gi` over N, ALL matches, left to right. Words before the name are allowed: no prefix group, no lookbehind. For each match, V = original index of the first character after the separator that is not a mark or blank (end of line if none). `wrapped = D exists and D < V`. The first wrapped match on the line wins; its sepEnd is the original index just after the separator. No wrapped match: the line is left to the other rules (`the token: leave this prose alone`, `const token = await getToken();`, `my_token: x`).
   This closes pass-2 H1 (`token: prose; **password**: hunter2`: `token:` is unwrapped, so the scan goes on and `password:` is wrapped) and pass-2 H2 (`**OpenAI API key: hunter2**`, `**The password: correct horse**`: D is the first `*`, before V).
3. Cost: one normalize pass and one `/g` exec per line. The alternation is fixed-length, a blank run is owned by at most one name end, the wrap test is one comparison. Linear in the line, so linear in the text.

## 2. Extent A, machine sinks: maskSecretLabelsToEnd(text, mask) -> string
Lines are read top down with the detector. At the first wrapped label, R = the original text from sepEnd to the END OF THE TEXT. If R trimmed is exactly one marker, keep it. Otherwise the output is `text[0..sepEnd] + " " + mask(R)` and the function returns. Nothing after a wrapped secret label survives: not on the label line, not on any later line, through any delimiter, list, quote, blank line, fence or `Word:` line (pass-1 H5 and pass-2 H3, every case). There is no block state, no terminator and no cap to exhaust: R is one slice and its length is O(1).
Markers, exact and anchored on the trimmed span: `«redacted \d{1,9} chars»`, `«redacted»`, `«redacted private key»`, `«redacted provider credentials»`. `isExactMarker(s)` is exported. Anything else (`«redacted TAILSECRET9»`, `«redacted 7 chars»TAILSECRET9`, a lone `«`) is content and is masked. f(f(x)) = f(x): the output ends in label + " " + marker.
Server: `redactSecretsForSink` runs A FIRST, then TEXT_RULES (whose MD slot is extent B; on A's output it finds label + marker and keeps it). Electron: `redactSecretsInLine` calls A FIRST, before the provider-connections rule, the env loop, AUTHORIZATION, BEARER, PEM_BLOCK and KEY_VALUE_PAIR (pass-1 H8: nothing eats the opening marks first). Its unit is the whole tail it is handed, so one wrapped label masks the rest of the tail; accepted for a support bundle.

## 3. Extent B, user-visible text: maskSecretLabelsOnLine(text, mask) -> string (replaces redactMarkdownLabels; the MD slot moves to FIRST in TEXT_RULES)
Why not A here: store.ts:837 rewrites every bot message forever, and bots write `**Password**: leave blank, then click Next` in ordinary step lists; A would erase the rest of such replies from the owner's transcript. Why not the current rule: it leaks on nine single-line shapes (table rows 1-7, 10, 11). B keeps the detector and masks by line, never parsing a value:
- R = the label line from sepEnd to EOL (a trailing `\r` stays outside). R trimmed is one marker: keep. Otherwise replace R with `" " + mask(R)`. Brackets, marks, backticks, escaped quotes, punctuation before a closing mark, fake markers and a second label on the line are all inside R.
- R blank (only blanks and marks): also mask whole the next non-blank line, looked for within the next 8 lines (`**password**:\n\nhunter2`, `\n- hunter2`, `\n> hunter2`, `\n**password**: hunter2`).
- R opens with `"`, `'` or a backtick run and that delimiter does not occur again in R: the value runs on, so this label switches to extent A (`"alpha1234\nTAILSECRET9"`, `"alpha1234\n\nTAILSECRET9"`, a quote over any cap). `don't` does not open with a quote, so prose keeps its apostrophes.
- Then the next line. Each line is read once: linear.
Known limit, user-visible only (Medium, documented): a bare value the writer split over two lines (`**password**: alpha1234\nTAILSECRET9`) keeps line 2, and a later line with no label of its own (`Bearer: abcdef…`) is judged on its own. Known-shape keys (sk-, ghp_, AKIA, JWT, ...) are masked anywhere by KEY_PREFIXES and JWT regardless.

## 4. Streaming (native.ts maskStreamDelta): running state per (thread, field), not a 512-character tail flag
State S = { line: the current unfinished line (text since the last `\n`), last 64 KiB; latched: false; masked: 0 }. Per delta `raw`:
- latched: write `mask(raw)`; masked += raw.length; once masked > MD_STREAM_CAP (64 KiB) write `«redacted»` instead. Nothing else of raw is written, ever: no blank line, `Word:` line or cap releases text (pass-2 H4, third case).
- not latched: run the detector over `S.line + raw`, line by line (complete lines, then the partial last line). First wrapped label: the part of raw before its sepEnd (clamped to raw) takes today's tail path for the other rules; the rest of raw becomes one mask; latched = true. No label: today's path. Then S.line = the text after the last `\n`, last 64 KiB. `**password**` + 600 spaces, then `: hunter2` is found because S.line holds the whole line (pass-2 H4, first case); `**password**:` then `\n\nhunter2` latches at the label, since A has no empty-value exception (second case).
- Reset: the thread's next `in` entry (owner to engine: a new prompt or tool result) resets S for every field. Eviction at STREAM_TAIL_THREADS removes the oldest UNLATCHED entry only; a latched entry lives until its reset.
- Linear: each delta is scanned once together with a prefix bounded by the line cap.
