# Terms acceptance

Murage asks the owner to accept the Terms of Service and Privacy Policy (https://murage.ai/terms-of-service, https://murage.ai/privacy-policy) once, on a screen that blocks the app until they tick "I am 18 or older and I agree to the Terms of Service and Privacy Policy" and press Accept. The Quit button (desktop app) closes Murage instead.

- **One version constant.** `TERMS_VERSION` in `shared/terms.ts` (the "Effective" date of the published terms). Change it when the terms change and every install is asked again, once, on its next open.
- **Where it is recorded.** `terms-acceptance.json` in the data folder (mode 0600): the terms version, the time, and the app version. It is the server's record, not browser storage, so it survives reinstalls, cleared browsers and other devices. Routes: `GET /api/terms`, `POST /api/terms/accept` (route class "companion": the desktop app or the owner's paired phone; any other caller gets the unknown-route 404, so a bot's shell cannot accept for the owner).
- **Phones and browsers.** The same screen appears on the paired phone of an install that has not accepted; accepting on either covers the install. The companion doors forward `GET /api/terms` and `POST /api/terms/accept` with the launch proof (`OWNER_DECISION_ROUTES`), so a paired phone shows the gate and can accept; a door without the proof can never accept. Quit is offered in the desktop app only.
- **Background work.** Routines and channels are not stopped for an install that has not accepted yet. Only the screen gates use.
- **Headless, cloud and automated runs.** There is no screen to tick. The operator who has accepted for that install sets `MURAGE_TERMS_ACCEPTED=<TERMS_VERSION>` (for example `2026-10-10`) in the server's environment. It counts only when it names the exact current version, writes nothing, and is not offered anywhere in the app. The e2e rigs set it (`scripts/e2e-environment.mjs`, `MURAGE_TERMS_PENDING=1` opts out); fixture servers seed the record (`launchVerificationServer`, `terms: "pending"` opts out).
- **Installers.** The Windows installer shows a license page and the macOS disk image a license agreement, both with `build/license.txt`, a short notice that points at the published terms. The legal text is never embedded. In-app updates install silently and show neither.
- **A failed check keeps the gate up.** If the terms check cannot be answered (network, HTTP error, malformed reply) the screen shows "couldn't check, retrying" with a Retry button and retries on its own (2 s, 4 s, 8 s, 16 s, then every 30 s); only an answer from the server lets the app mount. Routines and channels keep running server-side meanwhile.
- **Fixtures.** Packaged smokes that open a fresh profile seed the record (`scripts/terms-fixture.mjs`); `scripts/smoke-mvp-mac.mjs` is the one that accepts through the UI.
- **Residual (accepted).** The record is a plain file under the owner's OS user, and the owner's own Full-access bots run as that same user, so the file is not a security boundary; the clickwrap exists for the human owner's acceptance in the UI.
