## Implemented and checked in bounded fixtures

- Saved reports recover their normal message/card rendering when an interruption
  or thread switch interrupts the reply animation. Both failures reproduced;
  three focused component cases and client/server types passed.
- Browser profile saves reject stale lists before applying removals. The three
  final compatibility cases passed on Node 24, retaining earlier API/UI evidence.
- Flux uses a canonical connection with explicit credential choices and preserved
  existing aliases/session identities. Focused backend and joined UI evidence is
  accepted; no live keys were migrated by this work.
- Inbox/Files navigation messages and account safety actions have additions in
  seven languages. These are agent-authored translations with scoped catalog and
  component checks, not complete or human-reviewed application localisation.
- The candidate retains onboarding, persistent Inbox, saved Files, independent
  thread settings, named accounts and scoped-memory work with their existing
  evidence. This note does not reopen or broaden those feature checks.

Fuigo is pinned to **1.0.10**, with tarball and executable digests in
`scripts/prepare-fuigo.mjs`. A native macOS synthetic loopback driver check passed;
customers do not need to install Node.js for the bundled engine. Linux/Windows
ARM64 packages have recorded pins but are explicitly not stageable by the current
header-verification path. Pinning is not platform qualification.

## Native evidence and limits

Native macOS Files dispatch has actual preload/handler Open/Reveal evidence for a
text file; editor rendering and packaged Windows/Linux behavior remain unverified.
Native macOS Flux checks cover preload IPC, persistence, busy refusal and rollback
using a fixture encryption adapter. They did not call OS Keychain/safeStorage or
qualify a complete packaged application. Real account sign-in is not proven by
these synthetic checks.
