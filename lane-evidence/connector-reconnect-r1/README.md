## Behavior and limits

- Buffer uses the documented read-only `BUFFER_GET_ACCOUNT_CONTEXT` operation, explicitly selecting each account, at most once per five minutes. Four reads run concurrently, capped at 16 per pass. Each transport attempt has a five-second timeout; the existing transport may retry a connection refusal. No provider write is used as a probe. Source: https://docs.composio.dev/toolkits/buffer.
- Broker inventory accepts an optional sanitized `accounts[].expiresAt` in Unix milliseconds and preserves it in the cache. A known expired grant is detected even if status remains ACTIVE. This defines the client contract; it does not claim that every deployed broker supplies it.
- MCP sign-ins with known access expiry are scheduled even without a refresh token. Sign-ins without expiry refresh on a bounded schedule, or make a guarded read-only initialize probe when no refresh token exists. A terminal 401 marks only the unchanged saved credential.
- Composio's deprecated refresh endpoint is deliberately not used as a health check: its documentation says it no longer validates credentials. Source: https://docs.composio.dev/docs/auth-configuration/connected-accounts.
- Ownership uses the fingerprint recorded by a successful mint from the stored key. Token-only replacements do not prove proactive same-owner renewal. The legacy rejection path remains compatible.
- Ledger persistence appends only changed records once per batch. Existing snapshot files remain readable. Incomplete final journal records are truncated before further appends.
- Desktop receipts require Electron's `show` event. Failure revokes the receipt. Persistent attempt counts enforce a one-minute backoff and at most three attempts per incident/home. A notification with no delivery event also times out. In-app incident rows remain available after that ceiling. Legacy v1 desktop receipts are not treated as confirmed delivery because they were written immediately after show(); the pending incident may be offered again once on upgrade.
- Approval decisions, card policy, stop lines and read-tool grants are unchanged. Fixture permission changes use the normal owner confirmation route. No new product copy was added; the existing eight-locale reconnect copy is reused.
- Native OS delivery and packaged desktop interaction are not qualified by these headless tests. No Mac was accessed.
