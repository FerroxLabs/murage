## Host fixture diagnosis and change

`SignalProcessHost.open` constructs ParkFs, checks quiescence, and barriers custody parents BEFORE invoking the injected storage guard or runtime verifier. The fixture previously supplied fake storage success, a fake runtime, PID 123, and synthetic process discovery, while leaving custody's native Windows security and directory-sync adapters active. POSIX `mkdir`/`writeFile` mode arguments do not install protected Windows DACLs. The fixture therefore cannot establish the owner-only DACL that ParkFs requires, and the failure is correctly reported as `kept-check/check`. This is a fixture mismatch, not evidence of a rename/lock failure: these checks precede metadata renames and spawning.

A second mismatch would follow the ACL mismatch: `syncParentDirectoryStatus(..., 'win32')` deliberately returns `unsupported`, and required exclusion barriers must refuse it. The host-mechanics fixture must explicitly model successful custody durability, just as it explicitly models a successfully fenced fake process. Production refusal policy is unchanged.

The fixture now supplies its owner-only SID/SDDL projection, reparse attributes from real lstat, new-entry protection seam, and a successful sync seam on Windows. Linux continues exercising its original native sync adapter. Overrides merge with those defaults, preserving fault injection. The direct ParkFs constructor in the tracked-live-child test uses the same fixture options. The real Windows fresh/rotated-log test still uses `createSignalStorageGuard` and `windowsSecurityRead` against native DACLs; every existing entry in that disposable fixture is protected during setup. Its child/custody remain synthetic. No production storage guard or durability policy is bypassed in the app.

Three additional tests run custody's Windows branch on Linux: successful startup/identity/stop and a persisted exact-child exit, broad DACL refusal before storage or spawn, and unsupported required-durability refusal before spawn. Existing pure `ownerOnlyVerdict`/`ownerVerdict` policy tests run in storage.test.ts. The compiler contract retains the full diagnostic assertion and receives the ordinary project's 45-second compile allowance instead of this standalone config's default five seconds.

Linux container result: 106 passed; 11 existing platform qualifications not applicable on Linux. The Windows-mode regressions are included. This does not qualify native Windows ACLs, rename semantics, or durability.
