# HighLevel r4 F0 contract

This is the S0 contract freeze for HL-WRITES-1019-r4, including odes4-hl.
It is an integration base, not a runnable HighLevel release. C1, C2, C4 and
hlc3 own the explicitly marked implementation stubs. Their implementations
replace the bodies; family slices replace their provisional declarations with
these imports. No family implementation is required at F0.

Paths below are repository-relative. Family modules use `./registry.ts` and
`./schemas/<family>.ts`; core modules use `./held-request.ts`, etc.

All 181 design ids are present. Read gates use `R`. Only ready rows have
non-null endpoint fields and can generate endpoints; absent rows are retained
with documentation URLs. Present specs are checked at load; completeness is
required only for `INTEGRATED_FAMILIES`, initially empty. S-INT owns wave 2/3
family-list updates and the final 17-family test.

`pathResourceSegment` indexes `path.split("/")`, including its leading empty
segment. Contacts bind the parent contact at index 2; note/task child ownership
is checked by their declared preflight reads. Contact self/bulk, child and
custom-field preflights include odes4-hl's corrections. Opportunity preflights
also retain the contact, user and pipeline proofs already used by the family;
its input schemas retain its public argument names. Wire schemas are separate
from argument schemas. The shared workspace-file reference is accepted only by
schema identity.

`FrozenSendCopy.fileOffset` and `fileLength` are null for non-multipart bodies;
for multipart they identify the file bytes in the fresh send copy. C2 must check
body hash and content type, independently recompute the v2 request digest and
compare that digest with the approval, then independently check the file-range
hash. Plain reads have no approved-digest argument.

`HighLevelActions.propose(context, tool, args, detail)` requires `detail.held`,
`kind`, `risk`, `escalation`, and `basis`. Operation, resource and wire hashes
come from the held request. `beginDispatch` returns `{ intent, held }`.
`ReviewDigestInput` binds all authority fields plus every `ActionBinding` field.
C2's terminal read guard surrounds send, release and projection together; it
settles once after the release decision and preserves a stale result.

Tool completions have no origin. Only tool starts and assistant-text
completions use the `originRequired` predicate; the type test pins this to the
runtime-event union. Runtime projection remains C4's implementation.

The freeze is `frozen-contract.json`, checked by
`node --experimental-strip-types scripts/highlevel-f0-snapshot.ts` and T-F4.
It records exported signatures and hashes manifest/schema data. Private members
and implementation bodies are omitted. `declare`/`async` syntax is normalized.
S-INT's family-list initializer is omitted, but its exported type is pinned.
Assigned implementation bodies and scheduled family-list updates are permitted;
changes to frozen signatures or manifest/schema data require a MAIN amendment.
`--write` is for S0 or an approved manifest amendment, never to silence drift.

The S0 T-D5 test pins the R/C/D freeze signature. Executing GET/POST freezes,
wrong-location refusal, upload IO, read release and action lifecycles requires
the assigned C2/hlc3 implementation and is verified in those slices and waves.
No S0 unit or type result claims a live server/conversation workflow works.

F0.1 adds request-aware response-hook overloads without removing any F0
signature or changing manifest/schema data. Its normative dispatch binding,
expected-target settlement and migration rules are in [F0.1.md](F0.1.md).
