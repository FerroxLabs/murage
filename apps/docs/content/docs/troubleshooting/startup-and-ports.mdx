The desktop app starts Murage's background service and shows its screens from this same computer. The service normally listens on connection number `8799` (a port). If another program already uses it, the desktop app picks another one by itself.

## App opens but never becomes ready

1. Quit every Murage window.
2. Confirm no old Murage process remains.
3. Start the app once and wait for the local harness.
4. If it still fails, inspect the desktop log.

On macOS, packaged logs are under `~/Library/Logs/Murage`. On Windows they are under the Murage log directory in `%APPDATA%`.

## The start screen names its step

If opening takes more than a few seconds, the start screen adds a quiet line such as "Step 37 · Opening your memory". The words say what Murage is doing: finishing what was saved last time, opening your memory, updating your data for this version, opening your conversations, loading your teams, projects or routines, checking your messages or skills, or "Getting things ready" for anything else. A fast start shows no line. A long step is normal after an update or a large history; Murage keeps waiting while the step number keeps moving, up to a limit; if the step stops moving for 5 minutes the start is treated as failed. Note the step shown if you open an issue.

## Development port overrides

Use `MURAGE_PORT` for a source-run harness. A packaged desktop build owns its server lifecycle and may choose a fallback if the preferred port is unavailable.

## Isolate a test profile

Developers can set `MURAGE_DATA_DIR` to run against a clean Murage data directory. This is useful for reproduction and screenshots without touching a real workspace.
