Murage is designed around a local owner, explicit capabilities, and narrow process boundaries. Local-first does not mean risk-free: an agent with tool or computer access can still act on the resources you grant it.

## Core boundaries

- Murage's background service runs the AI apps and only accepts connections from this computer.
- The app's screens learn only whether a key is saved, never the key itself.
- Each AI service's key goes only to the AI app that needs it.
- Risky actions become approval cards rather than implicit permission.
- Local computer control is a separate opt-in and per-bot selection.
- A paired phone can use only a short list of allowed actions, and each device has its own private sign-in.
- Cloud and VPS backends are validated before reuse.

## Your responsibility

- Review approvals, especially shell commands, file writes, and actions in connected services.
- Use dedicated environments for untrusted or destructive work.
- Give each bot only the AI service accounts and connected apps it needs.
- Revoke a lost phone or other paired device immediately, in Settings → Phone and other devices.
- Keep Murage and your AI apps up to date.

Security reports should be filed through the repository's documented security channel rather than disclosed in a public issue before a fix is available.
