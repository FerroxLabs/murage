Murage renders structured agent events as native conversation cards. Questions, choices, permission requests, tool activity, and failures remain attached to the task that produced them.

## Approval cards

When an engine supports approvals, Murage surfaces the request instead of hiding it in terminal output. Read the requested action and scope before approving it. Denying an action sends control back to the agent so it can choose a safer path.

## Ask, Auto and Full access

Choose how a conversation is approved from the chip beside the composer:

- **Ask** shows a card for each action that needs your permission.
- **Auto** keeps the bot working, but still stops at anything that looks destructive or sensitive: shell profiles, API-key variables, credential stores.
- **Full access** does not ask before running commands, reading credentials or personal files, or contacting other bots. It can be switched on only in the desktop app, and the first time for each bot you confirm a warning.

Some things still ask under Full access. A turn started by a webhook or a routine asks as it would under Auto, because someone other than you wrote that input or nobody is watching it. Image generation still asks before it spends. Questions your bot asks you still reach you, and a bot on Auto still asks once before it first uses your screen. Switch back to Auto or Ask at any time.

## Inspector

Use **Inspector** when you need more detail than the conversation provides. It is useful for following tool calls, reconnect attempts, engine output, and long-running work.

## When a run disconnects

Murage retries transient streaming failures. If retries end in an authentication or configuration error, fix the underlying engine rather than repeatedly retrying the task. See [Agent engine troubleshooting](../providers/troubleshooting.mdx).
