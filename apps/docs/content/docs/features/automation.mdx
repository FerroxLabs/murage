## Routines

A routine runs a bot once or on a schedule you choose. Open **Routines** in the sidebar to see every routine on a calendar (day, three-day or week view, filtered by bot), or open **Bot settings → Routines** for that bot's own. Each run uses the bot's model, tools and computer.

<ProductScreenshot name="docs-automations" alt="An empty Murage routines calendar ready for its first schedule" caption="Review work across a day, three-day, or week view and filter by bot." />

Run receipts distinguish queued, active, waiting on you, completed, missed, failed, and cancelled work. Murage must be running when a local routine becomes due.

## One conversation per routine

Each routine keeps one conversation, named after the routine. Every run happens in that same conversation, with a divider between runs, so runs no longer pile up as separate conversations. Open it to read what the routine did last time and what it is doing now.

## Where results go

When a routine run finishes, its result comes back to the chat where you set the routine up: the bot's final reply, the files and images it saved, and **Open run** for the whole run. A routine with no chat of its own (one made on the calendar), or whose chat was deleted, posts to the bot's main chat instead. A run that fails or is missed posts one line that says what to do next.

To keep results out of chat, open the routine editor and set **Advanced → Send results to** to **Routines list only**. Each run still stays in the routine's own conversation and on the Routines list. Room and project routines, webhooks and messaging-app routines keep their own delivery.

## Routine approval level

Each routine runs at its own approval level: Ask, Auto, Full access or No limits. Set it in the routine editor under **Advanced → Approvals for this routine**, or from the permission chip in the routine's own conversation: choosing a level there sets it for the routine.

A routine you have not set shows "Same as (bot name)" and follows its bot's level at the moment each run starts. So a bot on No limits no longer stops its own routines to ask. The routine's conversation, its editor and its approval cards all show the level that actually applies. Reading your keys always asks, at every level.

## Waiting on you

When a routine run hits a question or an approval, Murage tells you at once ("(routine) is waiting on you") and the run ends as **Waiting on you** instead of sitting until it times out. The card stays in the routine's conversation and can still be answered: open it with Review, answer the question or the approval, and the routine carries on from there.

A run waiting on your answer stops its time limit clock and waits for you.

## Always allow for this routine

An approval card raised by a routine run offers **Always allow for this routine**. It covers that same command or place for that routine only, and it holds across every later run, so the routine stops asking about it. Other routines and ordinary conversations with the same bot still ask.

Everything a routine is always allowed to do is listed in its editor under Always allowed for this routine, each with Remove. Reading your keys still asks.

## Overlapping runs

In the routine editor, "If the last run is still going" chooses what happens when a run is due while the last one is still running:

- **Skip this time**: scheduled times are skipped while a run is still going.
- **Queue one run**: one scheduled run waits until the current run finishes.

Run now is separate from both. Skipped runs are counted and a streak of failures is shown. "Stop if still running after" sets an optional time limit for each run.

## Routine problems

The problems count at the top of Routines counts failed and missed runs you have not opened yet. Press it to open Routine problems, a list of exactly those runs, with Mark all as read.

## Webhook triggers

A webhook is a trigger link: a private web address another app calls to start work for a bot. It runs the same kind of task as a routine, without a schedule. By default Murage listens for these calls only on this computer (`127.0.0.1:8800`). Work started by another app's trigger link asks for approvals the way Auto does, because someone other than you wrote what it says.

That listener answers only a status check and your private trigger links. Nothing else in Murage can be reached through it.

For developers: prefer sending the secret in a Bearer header, which keeps it out of web addresses and most logs. If the sending app cannot set headers, use the link with the secret inside it instead.

## Reaching a local webhook

For developers: to accept calls from the internet, pass only the trigger link listener through a tightly set up relay or tunnel. Never open Murage's main connection (port) to the internet.

<Callout type="warn" title="Murage must remain running">
  Routines and trigger links on this computer do not run online. Closing the desktop app stops them until you open it again.
</Callout>
