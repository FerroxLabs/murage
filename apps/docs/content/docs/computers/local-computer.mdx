Local control is off by default. The Electron main process owns the bundled CUA driver lifecycle so operating-system permissions are attributed to Murage rather than a background helper.

## macOS

The packaged app can request Accessibility and Screen Recording permission. After granting either permission, restart the control session when prompted so macOS applies the new grant.

## Ubuntu

Local control works on Ubuntu 24.04 GNOME with Xorg, as a Beta. Open the Computer panel, press **Enable local control (Beta)** and let the Cua Driver checks finish. Every local action asks you first. On Wayland, local control stays off until its input protection is validated: sign out, choose **Ubuntu on Xorg** at the login screen, and This computer is ready to use. Chat, screen preview, Cloud and Local VM work on both.

## Safety model

- On macOS, a bot left on **Auto** can use this computer once local control is installed, but it asks you once before it first acts on your screen. Choose **Allow for this bot** and Murage remembers it for that bot. Choose **Don't allow** and Auto keeps that bot off your screen. To change your answer, open the bot's Computer panel and choose **Ask again**.
- Bots that already used this computer before this check existed keep working without the question: bots with Auto mode on, and bots you had already approved on this computer.
- A bot you set to **This computer** is never asked, because choosing it is your answer. Set a bot to **Off** if it should never touch your screen.
- On Linux, a bot receives this computer only when you choose **This computer** for it.
- Risky actions still surface through the approval flow.
- Missing permissions, unexpected binaries, unsupported desktop sessions, and failed health checks fail closed.
