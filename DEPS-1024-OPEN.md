# 1.0.24 dependency freshness: what moved and what is owed

Moved on fix/1024-deps: bundled Chrome headless shell 158.0.8127.36 -> 158.0.8127.88 (all four desktop pins and the Windows SAC allowlist hashed from the official archives); scripts/engine-versions.json manifest with a drift test. A Chrome bump moves five places, not three: the bundle spec pins, build-inputs/allowlist, and the two per-OS identity pins (server/browser-windows-identity.ts WINDOWS_BROWSER_IMAGE_PINS.chrome.bytes, server/browser-macos-identity.ts MAC_BROWSER_PAYLOADS.chrome.payloadSha256). server/browser-macos-pinned-assets.test.ts checks both against the real pinned executables (needs network or a seeded MURAGE_PIN_FIXTURE_DIR). ci/checkahead-downloads.tsv D034-D037 carry the archive hashes.

Owed, each needs an owner step this lane could not take:
- agent-browser 0.36.0 -> 0.45.0. The shipped engine is the Murage vendor build (control-token patch, Windows no-console patch, glibc 2.28 Linux build), not the upstream binary. Moving it means rebasing those patches onto 0.45, building 7 targets in CI, publishing a browser-engine release on FerroxLabs/murage and hashing the assets into server/browser-engine-release.ts, then the native end-to-end run that file's header requires. Publishing is outward-facing and needs MAIN's go.
- CUA driver 0.55.0 -> 0.63.x. Upstream marks every 0.61 to 0.63 release as a pre-release. Moving the pin needs new Windows and macOS provenance receipts (scripts/cua-driver-0.55.0-*-provenance.json, shared/cua-driver-windows-pins.mjs, contract version 0.9.0 check), SBOM and notices regeneration, and the call-site review against the driver changelog. MAIN should confirm pre-release pins are acceptable first.
- Fuigo 1.0.43 -> 1.0.48. scripts/fuigo-bump.mjs is the gate: it needs a FerroxLabs/fuigo checkout at v1.0.48, a human-reviewed hunks file for the folder-trust files (1.0.43 to 1.0.48 diff) and either real-turn evidence or `--real-turns-owed`. No reviewed hunks exist, so the pin was not moved.
