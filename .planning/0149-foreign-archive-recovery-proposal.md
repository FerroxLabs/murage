## Concrete route

Use the existing validated Murage installation ZIP and existing `restoreInstallation(newRoot, archive, inspectedHash)`. It already supports an absent destination, obtains its own/delegated lease, journals the switch, preserves its own transaction receipt, creates `restore-review.json`, disables engines/schedules/automatic bot authority and clears connection state. Do not back up, copy, rename, acquire or release the blocked original. Its primary/child/reaper anchors are never operation targets. A valid archive is the input; this route cannot salvage a foreign-owned raw directory without an independently established safe snapshot.

The recovery window offers "Restore backup to a separate installation" when current ownership inspection has a foreign-host blocker. Choosing the archive is read-only with respect to installation data. Existing `plan-restore` runs without a lease token and returns the private selection/hash. After preview, a native confirmation with Cancel default names the archive, retained original, exact new directory, backup-only history and paused review requirement. Only after consent does main allocate the destination and run restore. Renderer sends a selection ID, never paths/hashes/commands.

Destination default: a fresh exclusive container `<userData>/recovered-installations/<uuid>/`, with absent leaf `data`. Main generates the UUID; canonical containment checks reject userData/recovery storage overlapping the original in either direction and reject existing/symlinked containers. No folder chooser or broad profile manager is necessary. The actual `data` leaf remains absent until the existing restore transaction installs it, avoiding a meaningless retained empty original. Acquire a primary lease for that leaf in main; pass only its delegated capability to the recovery worker. Assert its canonical root/anchor differ from the original and remain inside the exclusive container before dispatch. Same-UID hostile ancestor races remain the existing lease protocol's explicit limitation, not a new guarantee.

After a successful worker exit and validated receipt, atomically persist a bounded strict startup-selection record outside both installations, in userData. The record binds the originally requested root, selected generated root, snapshot/hash/transaction identity and container identity. Retain an immutable operation receipt in the new container so a failed selector write is recoverable. Never publish selection before the restore review marker and matching receipt exist. On selector/write/worker failure, keep the original selected and retain the new candidate/journal/receipt; report its exact retained location without deleting it. Release only the newly acquired lease after the worker actually exits.

Then relaunch normally. Startup resolves `MURAGE_DATA_DIR ?? home/.murage`, applies only a selector bound to that exact requested root, validates the generated target/container, acquires its ordinary lease and hits the existing restore-review barrier. Missing/tampered selected data must raise recovery instead of silently creating a blank installation or falling back to the old one. The existing review -> native approval -> activate -> relaunch flow completes entry with engines/schedules disabled. An explicitly different MURAGE_DATA_DIR must not inherit another root's selection. Guard legacy migration when selection is active, since `env.MURAGE_DATA_DIR === undefined` alone is insufficient for a selected recovered default.

## Required input and limits

No unresolved product-choice blocker: managed destination and explicit native confirmation are sufficient defaults within the authorized scope. Actual customer execution requires an existing valid Murage installation archive. If none exists, this route must say so; it cannot manufacture proof that the foreign source is stopped or safely copy its live files. Do not request or collect the private archive in chat.

Restoration contains history and deletion records only through the selected backup snapshot. `mergeDestinationMemoryDeletions` sees an absent new destination and returns backup-only; it cannot import newer tombstones from the unowned original. Disclose that backup date/history limit in confirmation; do not claim latest-data preservation or latest deletion reconciliation. Original data remains retained for later owner-safe reconciliation. An archive has validation/hash guarantees, not cryptographic proof of how an external producer captured it.

A selector in userData persists normal launches/reboots; it does not update existing OS login entries or external launchers pinned to another MURAGE_DATA_DIR. Native sign-in provider behavior stays outside this package unless current caller evidence establishes a required integration failure.
