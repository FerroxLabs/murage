## Useful compatible gaps / explicit policy choice

1. **Stale profile-list save — concrete source-level lost-update risk, no runtime reproduction.** `src/components/SettingsModal.tsx:396` and its deletion path send the complete edited list without an expected snapshot. `server/index.ts:11818` checks partition/routing/cleanup safety but not the caller's base list. The serialized configuration gate prevents simultaneous mutation, not a sequential stale save: windows A/B load `[P]`; A adds Q; B later renames P using `[P-renamed]`; Q is interpreted as a removal. Existing removal checks can block active use, but they do not reject every stale list. Upstream `server/index.ts:12362` at e6660cb compares optional expectedBrowserProfiles; its shared manager supplies the expected list. Small compatible proposal for root: owner-route compare-and-swap field, canonical profile projection, conflict409 plus refresh message, carried by every full-list editor. Preserve current cleanup and partition rules. This is an explicit follow-on decision, not permission to edit or reopen a cap.

2. **Other authorized human viewers during takeover — intentional-policy decision, not a demonstrated Murage defect.** Upstream `server/browser-live.ts:207` withholds frames from every viewer except the holder, and `:345` hides URL/tab messages. Murage `server/browser-owner-api.ts:13` returns frame after owner-authority validation; `server/browser-control.ts:93` checks generation but not holder identity. `server/index.ts:7289` derives owner from desktop/companion plus installation realm, not a per-window viewer ID. Consequently another authenticated human surface authorized for that bot/profile can receive current frames while a human holds it. Murage0.1.49 is single-operator; no unauthenticated access, cross-user exposure, or agent privacy bypass established. If private-per-viewer takeover becomes desired, it requires explicit per-viewer identity + frame/status filtering—not merely a renderer hide. Keep current stronger agent protected-document barrier regardless.

3. **Profile-manager/tabs UI convenience — compatible but not necessary for architecture parity.** Active UnifiedBrowserPanel has profile switching and address/takeover controls (`:70–85`); create/rename/delete remain in Settings. Upstream shares one manager across both surfaces and adds tabs/back/forward/reload. Reuse current owner APIs if separately prioritized; no broad toolbar rewrite required to close this source review.
